# Piano Auto Sustain 2.1：自动录制音符与 CC64 设计规格

日期：2026-10-11  
品牌：Amu music  
目标版本：2.1.0

## 1. 目标

普通用户启动 Piano Auto Sustain Recorder 后直接演奏。宿主接收到的是已经处理好的 MIDI 流，其中同时包含原始音符、原始非踏板控制器以及自动生成的 CC64。录音期间钢琴音源实时发声；录音结束后，MIDI Part 内保留音符和 CC64，即使关闭插件、替换音源或导出 MIDI，延音演奏仍然存在。

用户不需要理解 Cubase MIDI 插入分隔线。首次使用最多完成一次键盘选择和一次轨道输入选择；使用随附的 Cubase 轨道预设或工程模板时，轨道输入预先指向 `Piano Auto Sustain`。

## 2. 产品组成

### 2.1 Piano Auto Sustain Recorder

Recorder 是 2.1 的默认入口。它负责：

- 枚举并打开实体 MIDI 输入；
- 创建客户端可见的虚拟 MIDI 端点 `Piano Auto Sustain`；
- 将音符送入共享的 `PedalEngine`；
- 按演奏时序输出音符与自动 CC64；
- 记忆设备、通道、延音参数、语言和主题；
- 显示键盘、虚拟端点和宿主连接状态；
- 在停止、断线、退出或异常时发送 CC64=0 与 All Notes Off。

### 2.2 Cubase MIDI 插入版

现有 `Piano Auto Sustain Cubase.dll` 继续提供，用于非破坏性实时延音和旧工程兼容。它不作为“把 CC64 直接录进 Part”的默认方案，因为 Cubase 是否记录 MIDI 插入输出由宿主分隔线控制，插件 API 无权替用户修改。

### 2.3 Cubase 预设与模板

发布包提供一个经过当前 Cubase 版本验证的轨道预设或最小工程模板：

- Kontakt/钢琴音源位置清晰标注；
- MIDI 输入设为 `Piano Auto Sustain`；
- 录音启用和监听路径说明可见；
- 不加载 Cubase MIDI 插入版，避免 CC64 被重复计算；
- 用户可以保存为自己的默认模板。

如果 Cubase 的预设格式不能稳定跨版本保存虚拟端点绑定，则提供最小工程模板，并在 Recorder 中用单屏引导指出唯一需要选择的轨道输入。

## 3. 虚拟 MIDI 后端

### 3.1 Windows 11 默认后端

优先使用 Windows MIDI Services 的 Virtual Device App Transport。Recorder 在进程存活期间发布 `Piano Auto Sustain` 端点；退出时端点消失，避免遗留无效端口。宿主通过兼容的 MIDI 1.0 或 Windows MIDI Services 接口连接客户端端点。

安装程序不重新分发未经授权或未经微软签名的系统驱动。它先检测 Windows MIDI Services：

1. 可用：直接启用原生虚拟端点；
2. 未安装但系统兼容：打开微软官方安装入口并在安装后复检；
3. 不兼容：进入外部虚拟端口兼容模式。

### 3.2 Windows 10 与兼容模式

Windows 10 以及缺少 Windows MIDI Services 的设备使用现有 Bridge 输出到用户已经安装的虚拟 MIDI 端口。产品可以检测常见端口并自动选择，但不会静默捆绑许可或签名状态不明确的第三方驱动。

兼容模式明确显示一次性安装/选择步骤。完成后保存端点稳定标识并自动重连。

### 3.3 后续平台

macOS 后端使用系统 IAC/虚拟 MIDI 能力；Linux 后端使用 ALSA/JACK MIDI。2.1.0 的正式二进制范围仍为 Windows x64，其他平台只有在对应构建、签名和实机宿主矩阵通过后才标注支持。

## 4. 数据流

```text
实体 MIDI 键盘
    ↓
Recorder 输入端
    ↓
输入过滤与通道归一化
    ↓
PedalEngine（和弦保护、低音变化、延音尾部）
    ↓
有序输出：原始 MIDI + 自动 CC64
    ↓
虚拟端点 “Piano Auto Sustain”
    ↓
Cubase / 其他宿主轨道输入
    ↓
同时送往钢琴音源与 MIDI 录音 Part
```

Recorder 保留 Note On、Note Off、弯音、触后、调制和除 CC64 外的控制器。自动模式拥有 CC64：实体踏板 CC64 默认被替换，避免双重踏板；高级设置允许“自动优先”“实体优先”和“合并”三种策略。

同一时间戳的输出顺序固定为：必要的 CC64 变化先于 Note On，Note Off 保持原始顺序。所有输出使用单调时钟，宿主录制时刻由虚拟端点接收时间确定。

## 5. 自动连接与首次体验

首次启动：

1. 检测虚拟 MIDI 后端；
2. 若只有一个可用实体键盘，自动选择并立即开始；
3. 若有多个键盘，显示卡片列表供用户选择一次；
4. 发布 `Piano Auto Sustain` 端点；
5. 显示“在宿主中选择 Piano Auto Sustain 作为轨道输入”；
6. 检测到宿主客户端连接后，状态变为“可以录音”。

后续启动自动恢复上次设备。设备缺失时不错误连接到名称相似但标识不同的设备；设备重新出现后自动恢复并先发送安全释放消息。

应用支持“随 Windows 启动”，默认关闭，由用户明确启用。关闭主窗口时可选择退出或缩至托盘，并记住选择。

## 6. 用户界面

主界面延续现有中英文和五套主题，默认只显示演奏所需信息：

- 大型踏板动画与“已释放 / 延音中”；
- 三段连接状态：键盘、Piano Auto Sustain 端点、宿主；
- 当前输入设备；
- “录制 CC64”状态和最近输出值；
- 自动踏板开关、低音界限、延音时长；
- 一键 Panic。

设备、通道、实体踏板策略和启动行为放入高级设置。诊断页显示输入音符、输出音符、CC64 数量、丢弃消息、重连次数和最近错误，但不记录演奏内容或工程名称。

## 7. 状态与配置

用户配置写入应用数据目录，采用带版本号的 JSON：

- `schemaVersion`；
- 输入设备稳定标识与显示名称；
- 后端类型与虚拟端点标识；
- 通道过滤；
- `SustainSettings`；
- 实体踏板策略；
- 语言、主题、窗口行为；
- 自动连接和随系统启动选项。

配置写入采用临时文件加原子替换。损坏配置被备份后恢复安全默认值。2.0 Bridge 配置若存在则迁移；无法识别的字段忽略，不阻止启动。

## 8. 故障与安全处理

- 输入设备断开：立即停止处理，向仍可用的输出发送 CC64=0 和 All Notes Off；等待同一稳定标识返回。
- 虚拟端点失败：停止转发并明确显示错误，不回退到可能形成回路的任意端口。
- 输入和输出相同或检测到消息风暴：立即断开输出并进入“检测到 MIDI 回路”状态。
- 应用退出、系统关机、休眠、设备切换：执行安全释放；释放失败写入诊断计数。
- 宿主尚未连接：继续保持端点，但不把这视为错误。
- 多宿主同时连接：Windows MIDI Services 后端允许时支持；状态只显示“已连接”，不推测客户端数量。

## 9. 录音与播放规则

Recorder 模式下，轨道上不得同时启用 Cubase MIDI 插入版，否则会再次生成踏板。启动向导和说明文档明确这一点。

录制得到的 CC64 是最终演奏数据。回放时无需 Recorder 继续运行，只要钢琴音源读取 Part 内的 CC64。用户可以在钢琴卷帘控制器通道编辑 CC64=127/0。

对于已经录好但没有 CC64 的旧 Part，继续支持 Cubase MIDI 插入版实时生成，或用 Cubase 的“冻结 MIDI 修改器/合并循环内 MIDI”烘焙。

## 10. 测试与验收

### 自动测试

- 音符与 CC64 的输出顺序、通道和时间；
- 和弦、滚奏、同低音多音、八度、换和弦与长尾；
- 实体 CC64 三种策略；
- 设备唯一/多个/缺失/重连；
- 虚拟端点创建失败和宿主连接状态；
- 回路检测、消息风暴、停止和退出安全释放；
- 配置保存、损坏恢复和 2.0 迁移；
- 中英文、五主题以及 100%/150%/200% 缩放快照。

### Windows 实机验收

- Windows 11 x64 + Cubase 15 + Kontakt：录音时实时发声；Part 同时出现音符和 CC64；关闭 Recorder 后回放延音不变。
- 至少一个其他 VST3 宿主：选择虚拟输入后可实时演奏并录下 CC64。
- 拔插键盘、停止录音、切换工程和异常退出后无卡音。
- 旧 Cubase MIDI 插入工程仍能加载 2.0/2.1 DLL，插件身份保持不变。

### 发布标准

只有自动测试全部通过且完成上述 Cubase 实机录音验收，才生成 2.1.0 正式包。未实测的平台保留“待验证”标记。

## 11. 发布结构

Windows 2.1 发布包包含：

- `Piano Auto Sustain Recorder.exe`；
- `Piano Auto Sustain Cubase.dll`；
- 通用 VST3 版本；
- Cubase 轨道预设或最小工程模板；
- 后端检测和安装引导；
- 中英文快速开始、兼容性矩阵、许可证和 SHA256；
- 对应的 2.1 源码压缩包。

2.0 发布包移入历史备份。所有公开文件、Windows 资源、界面和清单统一标记 `2.1.0`，插件界面显示 `2.1`。

## 12. 明确不做

- 不让插件静默修改 Cubase 全局首选项或工程路由；
- 不捆绑来源、许可或签名状态不明确的虚拟 MIDI 驱动；
- 不在 2.1 内置钢琴采样或 Kontakt；
- 不宣称未构建、未签名、未实测的平台已经兼容；
- 不把演奏音符或工程内容写入日志。
